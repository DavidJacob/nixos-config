# AGENTS.md

Guidance for AI coding agents working in this repo: NixOS + Home Manager +
dotfiles for David's three laptops, in one flake. David is learning NixOS, so
explain what a change does and why, and keep comments in the code
beginner-friendly. Open items and the reasons behind less obvious choices are
in `docs/notes.md`.

## Machines

| Flake name / hostname | Machine                               | Notes                                  |
| --------------------- | ------------------------------------- | -------------------------------------- |
| `maple`               | Acer Swift 3 SF314-59, Intel Iris Xe  | personal                               |
| `work`                | ThinkPad T14 Gen 7, AMD Ryzen PRO 250 | Famedly; famedly-nixos module; YubiKey |
| `macbook`             | MacBook Pro 13" 2017 (MacBookPro14,2) | personal; not installed yet            |

All three use disko (`modules/disk-layout.nix`). The flake attribute name
equals the hostname, so `nixos-rebuild switch --flake ~/nixos-config` picks the
right machine.

## Layout

```
flake.nix                    inputs + mkHost for the three machines
modules/common.nix           system settings shared by all laptops
modules/disk-layout.nix      LUKS + LVM layout for disko (my.disk.device, my.disk.swapSize)
hosts/<name>/default.nix     per-machine hardware, disk size, extras, stateVersion
hosts/<name>/hardware-configuration.nix   generated, do not edit
home/common.nix              Home Manager, shared (defines my.repo)
home/{zsh,noctalia,neovim,cheatsheet}.nix
home/hosts/<name>.nix        per machine: git email/signing key, extra packages, home.stateVersion
hypr/hyprland.lua            Hyprland config, shared
hypr/hosts/<hostname>.lua    that laptop's own screen (output, scale, position)
nvim/                        LazyVim config
scripts/hwinfo.sh            hardware details for a new install (run on the installer)
INSTALL.md                   installing or reinstalling a machine with disko
docs/notes.md                open items, history, reasons
```

The repo lives at `~/nixos-config` on every machine (`config.my.repo`). Never
hard-code `/etc/nixos`.

## Testing changes

- Flakes only see files git tracks: `git add` new files before evaluating.
- Check all machines evaluate (fast, builds nothing):
  `nix flake check ~/nixos-config`
- Build without switching:
  `nixos-rebuild build --flake ~/nixos-config#<name>`, then `rm result`
  (type exactly `rm result`, no trailing slash).
- Apply: `nixos-rebuild switch --flake ~/nixos-config --sudo`
  (alias `rebuild`). Use `--sudo`, never `sudo nixos-rebuild`: git refuses a
  repo owned by another user.
- Don't switch, commit or push without asking David first.
- Disk layout changes: preview with disko's `--dry-run` (see INSTALL.md). Never
  run disko yourself, the user will always do it.

## Hard rules

- **Never commit secrets.** They're added by hand on each machine:
  - Fleet enrollment key (work): `systemd-creds encrypt` →
    `/etc/credstore.encrypted/fleet-enroll-key`
  - Work email: `~/.config/git/work-identity`, pulled in via
    `programs.git.includes` in `home/hosts/work.nix`
  - GPG keys: only key IDs go in `home/hosts/<name>.nix`. maple has its own
    key; work's key is on Famedly YubiKeys.
- **Never change `system.stateVersion` or `home.stateVersion`.** They record the
  release each machine was installed with (all three: 26.11). Only a full
  reinstall may set a new value.
- **Don't edit `hardware-configuration.nix`.** It's regenerated by
  `nixos-generate-config --no-filesystems` (disko provides mounts, LUKS and
  resume). Put changes in `hosts/<name>/default.nix`.
- **Avoid package `override`s that force source builds** (Element once took
  1.4 GB of compiling). To add flags, wrap the pre-built package with
  `symlinkJoin` + `wrapProgram`, as `home/hosts/work.nix` does for Element.
- **Never run the disko commmand**: only ever print a command to be
  copy pasted by the user for them to review and run themselves.
- **Update `docs/notes.md` when making code changes:** keep the docs
  in sync with the live code by making sure what is documented matches
  what's in the config. Update the notes with an explanation when
  making code changes where the reason is not obvious.

## Nix style

- Group repeated attribute prefixes (`home = { … };` instead of several
  `home.x` lines); statix flags repeated keys.
- Machine-specific packages go in `home/hosts/<name>.nix` or
  `hosts/<name>/default.nix`, not in the shared files (e.g. Element is
  work-only).

## Hyprland (0.57, Lua config)

- Config is `hypr/hyprland.lua` using the `hl.*` API, not `hyprland.conf`.
  Type stubs for lua_ls are linked at `~/.local/share/hyprland-stubs`
  (`hypr/.luarc.json` points there).
- `hypr/` is a writable out-of-store symlink: edits apply on save, no rebuild.
- Per-machine screen settings go in `hypr/hosts/<hostname>.lua`, loaded via
  `/etc/hostname`, falling back to `scale = "auto"` if the file is missing.
  Positions keep the laptop centred under two 2560x1440 Dells:
  `x = 2560 - logical_width / 2`, `y = 1440`. Scales must divide the panel
  resolution evenly.
- `hyprctl dispatch` takes Lua expressions, e.g.
  `hyprctl dispatch 'hl.dsp.dpms({ action = "off" })'`. The old
  `hyprctl dispatch dpms off` syntax fails.
- hypridle runs as a systemd user service; it should not also be started from
  Hyprland's autostart (see docs/notes.md).
- Every keybind needs a `description` (it feeds the Super+/ cheatsheet).
- Noctalia: settings in `home/noctalia.nix` (`programs.noctalia.settings`),
  control via `noctalia msg …`.

## Neovim (LazyVim)

- `nvim/` is a writable out-of-store symlink, like `hypr/`.
- Mason installs most tools. Compilers and runtimes it needs (gcc, node, go,
  tree-sitter) come from `programs.neovim.extraPackages` in `home/neovim.nix`.
  `lua_ls`, `marksman` and `nil_ls` come from Nix with `mason = false`
  (`nvim/lua/plugins/nixos.lua`). nix-ld is enabled for Mason binaries.
- `nvim/lazy-lock.json` is committed; other machines sync with `:Lazy restore`.

## Formatting

- Lua: stylua, using `stylua.toml` at the repo root (2 spaces, 120 columns);
  `nvim/stylua.toml` matches it.
- Nix: nixfmt is available, but the existing files use aligned trailing
  comments that nixfmt would reflow; match the surrounding style.

## Read-only files from Home Manager

Files Home Manager manages are read-only store symlinks, e.g.
`~/.config/git/config` and `~/.config/gh/config.yml`. Change them through Nix,
not by writing to them. For `gh auth login`: choose HTTPS and answer "No" to
"Authenticate Git with your GitHub credentials?", otherwise gh tries to write
those files.

## Shell gotchas

- `ls` is aliased to `eza`; flags like `-t` differ. Use `command ls` when GNU
  `ls` behaviour matters.
- Default shell is zsh with starship, zoxide, fzf, direnv + nix-direnv.

## Work machine (Famedly)

- `inputs.famedly-nixos.nixosModules.default`: ClamAV, Fleet/orbit, Lix as
  the Nix implementation, mandatory signed commits.
- `hosts/work/default.nix` disables nixpkgs' own `services/monitoring/orbit.nix`
  because it clashes with fleet-nixos's module. Remove that once famedly-nixos
  handles it.
- No Gen 7 profile exists in nixos-hardware yet; uses `lenovo-thinkpad` +
  `common-cpu-amd` + `common-cpu-amd-pstate` + `common-gpu-amd`.
- YubiKey: `services.pcscd` (system) plus `~/.gnupg/scdaemon.conf` with
  `disable-ccid` and `pcsc-shared` (home), so gpg and ykman share the key
  through pcscd.
- GitHub: a separate work account (collaborator on this repo) is logged in to
  `gh` on this machine.

## MacBook

- Uses `nixos-hardware.nixosModules.apple-macbook-pro-14-1` (closest profile;
  provides the SPI keyboard driver needed at the LUKS prompt).
- Known gaps: the CS8409 speaker driver isn't packaged; Touch Bar untested.
